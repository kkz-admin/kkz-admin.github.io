# 尹禹皓个人博客设计方案

日期：2026-08-01  
状态：已确认，待用户复核书面规格

## 1. 项目目标

建设一个以招聘求职为核心目的、以个人技术博客为主要形态的静态个人网站。

网站不采用“在线简历”式的信息堆叠，而通过项目复盘、AI 工具实践与行业观察持续展示以下能力：

- 理解业务需求并将其转化为可执行方案。
- 使用 AI 工具提升流程效率和交付质量。
- 协调产品、业务与技术环节，推动项目落地。
- 对项目实施、产品协同和 AI 应用形成独立判断。

核心职业定位为：

> AI 项目实施与产品协同：将业务需求转化为可交付、可复用的解决方案。

目标岗位偏向项目助理、实施工程师及其他业务端项目岗位，不将网站塑造成纯开发工程师作品集。

## 2. 目标受众与成功标准

### 2.1 主要受众

- 招聘负责人和业务面试官。
- AI 产品、企业数字化、科创教育、智能硬件等相关团队。
- 对 AI 工具、项目交付和行业观察感兴趣的普通读者。

具体目标行业暂不限定，网站采用行业中性的表达方式。后续明确方向时，只调整职业标题、项目排序、简历措辞和文章侧重点，不改变网站架构。

### 2.2 成功标准

- 招聘者在首屏能理解作者的职业定位和核心价值。
- 访问者在三分钟内能找到代表项目、量化成果和联系方式。
- 网站具有真实博客的阅读体验，而不是简历内容的网页复制。
- 新文章可以通过 Markdown 和 Git 提交流程持续发布。
- 桌面端与移动端均保持可读、快速和稳定。

## 3. 内容策略

博客围绕三个内容支柱组织：

1. **项目复盘**：说明项目背景、目标、职责、行动、结果与反思。
2. **AI 工具实践**：记录 AI 工具进入真实业务流程的方法、校验和效率经验。
3. **行业观察**：表达对 AI 项目实施、产品协同和业务落地的持续判断。

首批建议文章：

1. 《我如何把 1500+ 份作品交付流程压缩到 7 天》
2. 《从需求梳理到上线：一套积分奖励系统的实施复盘》
3. 《我如何使用 Codex 协助完成项目拆解与问题排查》
4. 《AI 生成内容为什么仍然需要人工验收》
5. 《我理解的 AI 项目实施工程师：不是写最多代码的人》
6. 《从网络运维到 AI 项目协同，我的能力迁移路径》

项目案例不单独维护为一个顶层栏目。首页展示项目成果摘要，完整案例以“项目复盘”文章的形式沉淀在博客中。

## 4. 信息架构

### 4.1 首版可见导航

- 首页
- 博客
- 关于

### 4.2 预留但隐藏

- 留言

留言路由和导航能力可以在架构中预留，但首版不显示入口、不接入评论服务，也不出现未完成页面。未来开放时，再选择公开留言墙或私密联系表单。

### 4.3 页面职责

#### 首页

采用已确认的 A1“编辑式平衡”顺序：

1. 月影首屏：职业定位与个人主张。
2. 精选项目复盘：用一篇代表文章建立博客气质。
3. 代表项目成果：展示三个项目与量化结果。
4. 最近文章：覆盖三个内容支柱。
5. 关于摘要：个人经历与工作方式。
6. 行动入口：查看关于、下载简历和联系作者。

#### 博客

- 文章列表。
- 项目复盘、AI 工具实践、行业观察三类筛选。
- 标签、按时间归档和站内搜索。
- 文章详情、目录、阅读时间与相关阅读。

#### 关于

- 个人介绍和职业定位。
- 教育经历与校园经历时间线。
- 能力结构与工作方式。
- 专业照片，放在关于页而不是首页首屏。
- 简历摘要、公开版 PDF 下载与联系方式。

简历部分融合在关于页中，不建立独立简历页面。公开版简历应在上线前确认哪些联系方式可以公开；网站本身默认只展示用于求职的公开邮箱，不直接展示手机号。

## 5. 视觉设计

### 5.1 已确认方向

- 视觉方向：A“月影编辑部”。
- 首页结构：A1“编辑式平衡”。
- 灵感来源：Moonshot AI 官网的深色、克制、未来感和大留白。
- 原则：借鉴视觉语言，不复制 Moonshot AI 的标志、专有素材、文案或品牌识别。

### 5.2 视觉语言

- 以纯黑和深灰作为背景，正文使用灰白层级。
- 使用月弧、光晕、模糊文字和轨道线作为个人视觉符号。
- 导航采用低对比度、半透明或粘性效果。
- 卡片使用细边框、低亮度背景和中等圆角。
- 标题强调编辑排版与大留白，避免传统简历式密集列表。
- 数据只在项目证明区域突出，不将全站做成控制台或数据大屏。

### 5.3 动效原则

- 首屏使用轻量月食光晕、文字模糊到清晰和缓慢视差。
- 内容区使用滚动渐显和克制的卡片悬停反馈。
- 动效服务于层级和氛围，不阻塞阅读或导航。
- 遵循 `prefers-reduced-motion`；低动态模式关闭视差、模糊过渡和持续动画。
- 移动端降低光晕尺寸、粒子数量和阴影复杂度。

## 6. 技术架构

### 6.1 技术选型

- Astro
- TypeScript
- Markdown 或 MDX 内容集合
- 原生 CSS 为主，少量客户端 JavaScript 负责搜索和动效
- GitHub Actions 自动构建
- GitHub Pages 静态部署

首版不使用数据库、不建立常驻后端、不接入可视化 CMS。

### 6.2 发布流程

```text
Markdown 与图片
    -> Astro 内容集合校验
    -> 静态页面生成
    -> Git 提交并推送
    -> GitHub Actions 检查与构建
    -> GitHub Pages 发布
```

日常发布方式为 Markdown + Codex：作者提供想法或草稿，Codex 协助整理 Frontmatter、校对结构、预览检查并提交到 Git。

### 6.3 组件边界

#### 全站公共组件

- `SiteHeader`：首页、博客、关于导航。
- `MoonCursor` / `MotionLayer`：月影光晕、滚动渐显和低动态模式。
- `SiteFooter`：联系方式、版权与辅助链接。
- `SEOHead`：标题、描述、规范链接和社交分享元信息。

#### 首页组件

- `MoonHero`
- `FeaturedEssay`
- `ProjectProof`
- `LatestJournal`
- `AboutStrip`

#### 内容页组件

- `BlogIndex`
- `ArticleCard`
- `ArticleLayout`
- `TableOfContents`
- `RelatedPosts`
- `AboutTimeline`
- `ResumeDownload`

页面只负责组合组件；组件只负责单一展示或交互职责；内容存放在 Markdown 和集中配置文件中。

## 7. 内容模型

博客文章至少包含以下 Frontmatter：

```yaml
title: 文章标题
description: 用于列表和搜索的摘要
publishedAt: 2026-08-01
category: 项目复盘
tags:
  - AI 自动化
draft: false
featured: false
```

字段规则：

- `title`、`description`、`publishedAt`、`category` 为必填。
- `category` 只允许“项目复盘”“AI 工具实践”“行业观察”。
- `tags`、`cover`、`draft`、`featured` 为可选字段。
- `draft: true` 的文章不进入生产构建。
- 必填字段缺失、日期无效或分类不合法时，构建失败并指出具体文件。

内容目录建议：

```text
src/content/blog/     博客 Markdown
src/data/profile/     个人资料与项目摘要
src/assets/           需要构建优化的图片
public/resume/        公开版简历 PDF
```

## 8. 错误处理与降级

- 文章封面缺失时使用统一的月影占位视觉，不显示破损图片。
- 简历文件不存在时隐藏下载按钮，并保留关于页其他内容。
- 无效文章 Frontmatter 在构建阶段报错，不允许带病部署。
- 提供符合品牌视觉的 404 页面，并给出返回首页和博客入口。
- 外部链接使用安全属性并清楚标识。
- JavaScript 加载失败时，正文、导航和文章列表仍然可访问。
- 搜索不可用时，分类和归档仍可作为浏览路径。
- GitHub Actions 只有在检查与构建全部通过后才执行部署。

## 9. 响应式、性能与无障碍

- 以移动优先方式定义断点，并在常见手机、平板和桌面宽度检查布局。
- 使用语义化 HTML、可见键盘焦点、正确标题层级和图片替代文本。
- 所有正文和交互元素满足可读的颜色对比度。
- 关键内容不依赖悬停或动画才能访问。
- 图片使用合适尺寸与延迟加载；首屏关键资源单独优化。
- 字体优先使用系统字体或受控的少量字体文件，避免阻塞加载。
- 只在必要区域加载客户端脚本，保持 Astro 静态输出优势。

## 10. 验证策略

每次准备发布时至少执行：

1. TypeScript 与 Astro 内容集合校验。
2. 完整生产构建。
3. 内部链接、404 和资源路径检查。
4. 首页、博客列表、文章详情和关于页的桌面端视觉检查。
5. 主要移动端宽度的视觉与交互检查。
6. 键盘导航、低动态模式和基本无障碍检查。
7. Lighthouse 或同类工具的性能、SEO、最佳实践和无障碍检查。
8. GitHub Pages 基础路径和部署后链接抽查。

## 11. 首版范围

### 包含

- 首页、博客、文章详情、关于和 404。
- 三类 Markdown 博客内容。
- 精选文章、项目成果和最近文章模块。
- 博客分类、标签、归档和客户端搜索。
- 关于页的经历、能力、专业照片、简历摘要和 PDF 下载。
- 深色月影视觉、响应式布局与低动态模式。
- GitHub Actions 和 GitHub Pages 部署配置。

### 不包含

- 留言和评论功能。
- 独立项目页面。
- 独立简历页面。
- 可视化内容管理后台。
- 用户账户、数据库或其他后端服务。
- 双语版本。
- 自定义域名购买与 DNS 配置。
- 访问统计、邮件订阅和商业化功能。

## 12. 后续扩展

- 开放留言页，并按需要选择公开留言墙或私密联系表单。
- 接入自定义域名。
- 增加英文版本。
- 增加隐私友好的访问统计。
- 根据明确的目标行业调整首页标题、项目排序和内容推荐。
